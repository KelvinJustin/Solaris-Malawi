# Solaris Malawi — Frontend

React 19 merchant dashboard for Solaris Malawi. Single-page app built with Vite 7, TanStack Router (file-based), and Tailwind CSS 4. Wired to the cookie-based auth API described in [`backend/docs/architecture/authContract.md`](../backend/docs/architecture/authContract.md).

> For full project setup including the backend, see the [root README](../README.md).

---

## Setup

```bash
cp .env.example .env   # Windows: Copy-Item .env.example .env
npm install
npm run dev            # http://localhost:5173
```

`VITE_API_URL` (in `.env`) is the API **origin** without a trailing slash or `/v1`; the app adds the prefix itself. Defaults to `http://localhost:3000`.

The backend's `FRONTEND_URL` must exactly match this origin (e.g. `http://localhost:5173`), because credentialed CORS cannot use a wildcard origin.

## Authenticated Shell

Everything under `src/routes/_authed/` renders inside `AppShell` (`src/components/AppShell.tsx`): a sidebar on large screens that collapses to a slide-over menu on mobile, with the nav, the account status pill, the merchant's email, and Logout.

- **Account status** — `GET /merchants/profile` is fetched once by `ProfileProvider` (`src/lib/merchant-profile.tsx`); the sidebar and home page both consume it via `useProfile()`. Status labels and colour tones live in `src/lib/profile.ts` (`ACCOUNT_STATUS`).
- **Data fetching** — Use `useResource` (`src/lib/use-resource.ts`) paired with `<ResourceBoundary>` for any GET that feeds a page. The page then only describes its success view; loading, error, and empty states are handled uniformly by `src/components/states.tsx`. A 401 from any `useResource` call ends the session and redirects to login.

## How Auth Works

- Every request uses `credentials: "include"` (`src/lib/api.ts`). No token is ever read or stored in JS.
- On load the app calls `GET /auth/me` (`src/lib/auth.tsx`): 200 → logged in, 401 → logged out, network error → "Can't reach Solaris" with a retry button (not treated as an expired session).
- **Login** is two steps: `POST /auth/login` (password, emails a code) → `POST /auth/verify-login` (code, server sets the HTTP-only cookie) → `GET /auth/me` for the identity.
- **Register** does not log in; the merchant verifies their email (`POST /auth/verify-email`, `POST /auth/resend-verification`) and then logs in normally.
- **Logout** = `POST /auth/logout` (server revokes the token and clears the cookie); local state is cleared only after the server confirms.

## Project Structure

```
frontend/
├── public/            Static assets & favicon
├── src/
│   ├── assets/        Images & icons (logo.png)
│   ├── components/    Shared UI components (AppShell, states, etc.)
│   ├── lib/           API client, auth, profile provider, hooks
│   ├── routes/        TanStack Router file-based routes
│   │   ├── __root.tsx
│   │   ├── _authed/   Authenticated pages (home, payments, profile)
│   │   └── _guest/    Guest-only pages (index/login, register, verify-email)
│   ├── styles.css
│   └── main.tsx
├── .env.example
├── components.json    shadcn/ui config
├── vite.config.ts
└── vitest.config.ts
```

Routes live in `src/routes` and `src/routeTree.gen.ts` is auto-generated by the TanStack Router plugin.
